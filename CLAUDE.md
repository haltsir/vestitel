# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Vestitel is a menu-bar-only macOS RSS reader (SwiftUI `MenuBarExtra`, no Dock icon, no main window). Built with SwiftPM + Command Line Tools only — there is no Xcode project and the build never uses `xcodebuild` (Xcode happens to be installed, but nothing here depends on it). No external dependencies. One small Swift Testing target (`Tests/VestitelTests`, `swift test`) covers pure parsing and decoding (local events, Article decoding); UI and store behaviour are verified in the running app as described below.

## Commands

```sh
make app    # swift build -c release + package Vestitel.app (ad-hoc signed)
make run    # make app + open Vestitel.app
make icon   # regenerate Resources/AppIcon.icns from Tools/make-icon.swift
swift build # debug build, fastest way to check for compile errors
swift test  # parsing/decoding tests (Swift Testing, @testable import of the executable target)
```

The dev loop for verifying a change in the running app:

```sh
make app && pkill -f Vestitel.app/Contents/MacOS/Vestitel; sleep 1; open Vestitel.app
```

App state lives in `~/Library/Application Support/Vestitel/state.json`. Seeding or editing this file (while the app is quit) is the established way to set up test scenarios; deleting it resets the app. Setting `articles: []` and `seen: {}` while keeping `feeds` forces a full re-ingest on next launch (used to trigger the new-articles animation and re-parse with new fields).

For live tests that must not touch real data, launch a second instance with `VESTITEL_STATE_DIR=<dir> Vestitel.app/Contents/MacOS/Vestitel` — it gets its own state.json (seedable, e.g. with a feed served by `python3 -m http.server`) while the user's instance keeps running. Do NOT try `HOME=<dir>` for this: FileManager ignores it and the second instance will silently share and fight over the real state file. Addressing the test instance in AX by pid (`first application process whose unix id is <pid>`) is unreliable in practice: with two Vestitel processes System Events often can't find the popover window at all. For AX-driven UI tests quit the real instance first (`pkill -f MacOS/Vestitel`), run only the test instance, and relaunch the real one (`open Vestitel.app`) afterwards. For README screenshots, seed a demo state dir (public feed URLs and headlines, synthetic smart inboxes, muted keywords and local-source events; never bookmarks, archive or the sync path) and run it as a `VESTITEL_STATE_DIR` instance under `~/Library/Application Support/Vestitel Demo` so the Local Sources path reads sensibly; never place demo data at the real state path (the user objected). Capture each tab into `docs/screenshots/`; park the pointer outside the popover before each capture (hover reveals the row buttons), and re-check that the popover window exists (the one with `radio group 1 of group 1`, not a bare window count: the desktop widget panel is a window too) before every tab switch because the popover can close between steps.

UI verification is done by screenshotting the popover: open it via
`osascript -e 'tell application "System Events" to tell process "Vestitel" to click menu bar item 1 of menu bar 2'`
(this *toggles* — check `count of windows` first), read the window bounds via System Events, then `screencapture -x -R "x,y,w,h"`. All content sits under `group 1 of window 1`; the tab picker is `radio group 1` (Inbox=1 … Settings=5). Do NOT set text field values via AX (`set value of text field …`) — it bypasses SwiftUI bindings and buttons stay disabled; synthesize real clicks/typing instead. What works: `set focused of <text field> to true` then `keystroke "…"` and `key code 36` (Return) for text entry (find a field by `value of attribute "AXPlaceholderValue"`; `keystroke` can't type Cyrillic, use Latin test strings); AX `click` for standard buttons found by `title`. What doesn't: plain-style chip buttons (`SmartInboxBar`) and hover-gated `RowActionButton`s are not reachable through AX `click`, use `click at {x, y}` with screen coordinates computed from the popover bounds (a 2x screenshot pixel /2 + window origin); hover-gated buttons still need the pointer to have hovered, so a `click at` may only reveal them, and it's often quicker to verify that path by editing the state file. Button-style `Toggle`s (the Cleared tab's "Filtered (N)") also need `click at`.

## Architecture

Single module, `Sources/Vestitel/`. Everything runs on the main actor.

- **`AppStore`** — the one `ObservableObject`, injected as `@EnvironmentObject` everywhere. Owns all state, timers, fetching, persistence, and every user action. Views never mutate model data directly. Render-path caches (all main-thread, all invalidated by the data they derive from): `inbox` (filtered + sorted, reset in `articles`/`inboxHoldStart` didSet), `searchText(of:)` per article id (title/summary/tag never change for an id), `smartInboxUnreadCounts` (one pass for the whole chip strip; `SmartInboxBar` must not call `unreadCount(in:)` per chip, `ViewThatFits` evaluates every candidate strip), and `groupCache` (below). With ~900 inbox articles these are the difference between a popover that opens in ~100 ms and one that takes half a second.
- **`Models.swift`** — plain Codable structs. `Article` moves through a state machine: inbox (unread → read via `readAt`) → cleared (`clearedAt`) → purged. Time-based transitions happen in `AppStore.sweep()` (30 s timer): read articles clear after 15 min, cleared articles purge after 24 h. A `seen` id→date map prevents purged articles from re-ingesting: `ingest` refreshes the date on every fetch that still lists the item, and `sweep()` drops entries 30 days after that, so an id expires 30 days after its feed stopped carrying it (not 30 days after first sight, which let a slow feed's whole back catalogue resurrect at once). **Skip old articles** (`settings.skipOldArticles` + `maxArticleAgeDays`, off by default): `ingest` marks items published before the cutoff seen without adding them; local sources exempt. **Same-feed re-posts** (`duplicateIndex(feedID:title:)`): an item whose feed already holds an article with the same title (case/whitespace-insensitive) under a different guid is a republished story (dir.bg files one piece under two sections with "-1" appended), not a group: its id is marked seen and skipped, and the existing inbox article adopts the newer link/image/published only when the duplicate is newer (feeds list newest first, so the duplicate met is often the older one); read or cleared originals stay as they are. Sync adoption applies the same check, and `collapseDuplicateReposts()` (at load and after every sync merge) folds pairs that got in before the check existed, keeping the newest and carrying over a read mark. Titles compare on letters and digits only (quote style and punctuation differ between re-posts). Local sources are exempt: a script posting the same title nightly means every one. **Muted keywords** (`settings.mutedKeywords`): `mutedKeyword(matching:)` is a case-insensitive substring match over title + summary + tag (`searchText(of:)`, shared with smart-inbox filters), checked at `ingest` and on sync adoption; a hit is stored straight away as `.cleared` with `filteredBy = <keyword>`, so it never enters the inbox, never counts as "new", and expires with the normal 24 h cleared retention. `store.cleared` excludes filtered articles and `store.filtered` lists only them (the Cleared tab's "Filtered (N)" toggle). `settings.didSet` calls `applyMutedKeywords()` whenever the list changes: it clears matching inbox articles retroactively and returns articles whose keyword was removed to the inbox (with `fetchedAt = now`, so the inbox hold applies). `restore` clears `filteredBy`, overriding the filter for that article only. **Smart inboxes** (`settings.smartInboxes`, ordered, sources referenced by feed URL so exports stay portable): saved views over the inbox, each a list of OR-combined `SmartInboxFilter`s (`matches(_:_:)`: none = everything, else any filter matches); one filter = source in its `sourceURLs` (or any when empty) AND its keywords any/all as substrings of title + summary + tag. Pre-filters files decode via `SmartInbox.LegacyKeys` (top-level keyword/source fields become one filter). `selectedSmartInboxID` (in-memory) picks the view; `visibleInbox`/`visibleGroupedInbox` narrow `inbox`/`groupedInbox` (groups are built once over the whole inbox and then have non-matching members dropped, never regrouped per view), and the Inbox footer's Open All / Clear act on the visible set (`clearVisibleInbox`, labelled "Clear Shown" when scoped). `SmartInboxBar` in `InboxView` uses `ViewThatFits` over decreasing prefixes of the list, so as many chips as fit show in user order and the remainder land in a "More" menu; reordering (up/down) and the inline editor live in Settings. **Group by source** (`settings.groupBySource`, the Inbox header's `rectangle.3.group` toggle): `groupedInbox` returns one `TopicGroup` per feed (`sourceGroups`, `sourceFeedID` set, id `source|<feedID>`, newest feed first, a single article still a block) instead of topic groups; `GroupBlock` then wears the feed colour, shows the `SourceMark`, no banner, every row `.member` with `hidesSource`. Smart-inbox filtering, collapse and clear-group work unchanged.
- **`LocalSources`**: the ingress for other apps and scripts on this Mac ("things that happened"). Two transports, one model: a drop folder (`Application Support/Vestitel/Events/`, under `VESTITEL_STATE_DIR` for test instances) where a producer writes a JSON file holding one event or an array (`source` + `title` required; `url`, `summary`, `image`, `published`, `id`, `tag`, `symbol` optional; `tag` is a short "why it was posted" label, trimmed and cut at 40 characters, shown as a chip after the source name in the row, in compact rows too, and part of the keyword haystack; `symbol` is an SF Symbol drawn before it, dropped unless `LocalEvent.validSymbol` resolves it and there is a tag), and the `vestitel://add?source=…&title=…` URL scheme (`CFBundleURLTypes` in Info.plist, received by `AppDelegate.application(_:open:)`). Files are consumed on launch, on every `refreshAll`, and within ~1 s via a `FolderWatcher`; unparseable ones move to `Events/Rejected/` so they are visible but never retried. Each `source` maps to a `Feed` of kind `.local` with the deterministic URL `vestitel://source/<slug>`; that URL is only an identity (article ids, sync matching by URL, colour), never fetched: `refreshAll`/`refreshFeed` skip local feeds, the row has no refresh button, and `Feed.faviconHost` is nil so no favicon lookup hits the fake host. Events go through the ordinary `ingest` (uncapped, like store feeds), so the inbox hold, grouping, sync and the read/cleared/seen machine all apply unchanged. A removed source is recreated when its producer posts again (the tombstone is cleared, as in `addFeed`). URLs are buffered in `OpenURLQueue` because when the app is *launched* by a URL the delegate callback and `AppStore` creation race. To test the scheme, `open "vestitel://add?…"` goes to the running instance of the registered bundle, so with the real app quit it reaches a `VESTITEL_STATE_DIR` instance started from the same `Vestitel.app`; `lsregister -f Vestitel.app` after changing Info.plist.
- **`Updater`**: self-update from GitHub releases, ported from Ozonko. A daily check (12:30, ridden on `sweep()`, stamped in `lastUpdateCheck` before the request) reads `releases/latest`, and a newer tag is downloaded together with its `.zip.sig`, verified against the embedded ed25519 public key (CryptoKit; private half only in `~/.config/vestitel/release-key`), unpacked with `ditto`, checked for a matching plist version (`Updater.sameVersion`: plist "1.7" equals tag "1.7.0"), and staged in the temp dir. Unsigned or badly signed releases are refused, never installed. The swap waits until the app is idle (`popoverOpen == false`, retried on popover close and every sweep tick, never gated on `autoUpdateEnabled`; Settings shows an "Install Now" button while an update is staged, which forces the swap immediately): a detached `/bin/sh` helper waits for the pid to exit, `ditto`-replaces the bundle, and relaunches (`open`, or for a `VESTITEL_STATE_DIR` instance the binary with its env, so a test never spawns a second real instance). `lastRunVersion` lets the next launch post one "updated" notification. Off for test instances unless `VESTITEL_UPDATE_URL` points at a stand-in releases JSON (same shape as the GitHub API); the full cycle can be exercised with a scratch copy of the bundle, a plist-bumped zip signed by `Tools/sign-release.swift`, and `python3 -m http.server`. Self-downloaded updates carry no quarantine flag, so Gatekeeper is a first-install problem only.
- **`FeedParser`** — dependency-free RSS 2.0/1.0/Atom parser on `XMLParser`. Namespace prefixes are stripped to local names, so `media:content` arrives as `"content"` (shared case with Atom's `<content>`, disambiguated by the `url` attribute).
- **`TopicGrouper`** — clusters same-story articles across sources: union-find over pairwise links from keyword-Jaccard (language-agnostic) OR NL sentence embeddings gated on ≥2 shared-token weight AND on `NLLanguageRecognizer` saying the title is English — the English model maps text it can't represent (Cyrillic!) to near-identical vectors, so ungated it links any two Bulgarian titles as "semantically the same". Tokens drop <3-char words, numbers, and a bilingual (English + Bulgarian) stopword list of function words and news-rubric noise ("видео", "снимки", "млн", "breaking"…) plus ordinals, scoreboard words ("първа", "точки", "сезона", "мач": an NFL opener and a Levski defeat shared all three) and currencies/units ("долара", "евро", "барел": every price story shares them). A rubric label of two or three words before the first colon or bar ("Бизнес глобус:", "Три минути:", "Снимка на деня:") is dropped before tokenizing (`rubricBodyStart`): a feed's daily digests would otherwise share two tokens pairwise and chain into one group; single-word and all-capitalised prefixes ("Радев:", "Асен Василев:") are attributions and stay; hyphenated compounds stay whole ("22-годишна", "Е-79"); Cyrillic words of four or more letters go through `stem`, a light Bulgarian stemmer (Savoy 2007, the algorithm Lucene uses: article, plural, final vowel, fleeting е/ъ), so "точки"/"точката"→"точк", "хусите"/"хуси"→"хус", "градът"/"градове"→"град"; stems are internal keys only, the headline recovers the display form by re-stemming title words (single words and phrase windows alike). Stopwords are surface forms and are checked before stemming, so a stopword's stem can't swallow a real word ("прави"→"прав" must not drop "право"). Replaying the real inbox (~860 titles) through the stemmer added ten correct links and no false ones beyond an already-topical Sofia-transport group. Text inside quotes („…“, “…”, «…», "…") becomes a single phrase token, counted double in the shared-token shortcut — a shared quoted name is a strong same-story signal. Multi-word named entities ("South Korea", via `NLTagger` nameType, English-only) are the opposite: the joined phrase token absorbs its component words in the weighting so a shared name counts once, and the components stay in the set so "Trump" still matches "Donald Trump". Bulgarian has no name model, so `capitalisedRuns` stands in for Cyrillic-dominant titles: a run of ≥2 consecutive capitalised words mid-title ("Матилд Арсел", "Woman Unknown") is a name phrase, the sentence-initial word is skipped unless Latin-script, and Latin-script titles are left alone (Title Case would swallow them whole). Group **headlines** (`headline(for:titles:)`) rank shared tokens phrases first, then words capitalised mid-title, then the rest; two or more phrases make the whole label, otherwise up to three picks, and once a name or phrase is in, only one plain word joins it ("„Да, България“ · документи"), preferring the word that completes the name in most titles ("Стара планина", never a one-off "Русия атака" or an acronym's verb "ЕЦБ повиши"); quoted phrases display in „…“ so a comma inside them reads as one unit; all-caps words count as names; shown in the order they appear in the newest title, with adjacent capitalised picks joined into one part ("Асен Василев · Йотова": the sentence-initial word never starts a name run, so the join happens at display time), sentence case (no uppercasing in the view). A pair needs shared weight ≥ 2 to link at all — one shared word or name is never the same story. Pair candidates come from an inverted token index (a link needs shared weight ≥ 2, so pairs sharing fewer than two tokens and no quoted phrase are never compared; identical output to all-pairs, 10x faster on a ~900-article inbox). Embeddings are expensive: vectors are memoized per title here, and the resulting group *structure* (ids, not Article values) is cached in `AppStore.groupCache`, keyed on inbox composition + sensitivity, warmed at launch and right after ingest. When the inbox only *lost* articles since the cached grouping (clear, read countdown), `groupedInbox` regroups just the groups that lost a member (components can only split) instead of the whole inbox; that is what keeps clearing a row at ~50 ms instead of ~500 ms with hundreds of articles. Don't call `TopicGrouper.group` from view code — go through `store.groupedInbox`.
- **`NotificationManager`** — local notifications (UserNotifications). Two cases. (1) A feed fetch answered with a bot-challenge page (`AppStore.looksBlocked`: `cf-mitigated` header, or 401/403/429/503 + HTML body) sets a readable `lastError` and posts a notification with an "Open Website" action; once per block episode per feed (`notifiedBlockedFeeds`, in-memory), identifier keyed by host so repeats replace. (2) The launch after a self-update posts one "Vestitel updated" note (`notifyUpdated`, no category, so tapping it only dismisses). Authorization is requested lazily on first use. Banners aren't AX-clickable — verify delivery via `log show --predicate 'process == "usernoted"'`.
- **`DesktopWidget`** (`Views/DesktopWidget.swift`): the "big" Inbox on the desktop, an AppKit `NSPanel` rather than a WidgetKit widget (an extension bundle would need its own signing and an app group, which the SwiftPM ad-hoc build can't produce). `DesktopWidgetController.shared` is attached to the store in `VestitelApp.init` and follows `settings.desktopWidgetEnabled` through Combine. The panel is borderless, non-activating, at level `desktopIcon - 1` (above Finder's wallpaper window, below its icons, so it survives "show desktop" and Mission Control via `.stationary`), on every Space, movable by background and resizable by its edges; its frame is remembered in `settings.desktopWidgetFrame` (with `desktopWidgetTitleSize` and the toggle excluded from `syncableSettings`, screens differ per Mac) and dropped if no attached screen intersects it. Content is an `NSVisualEffectView` (hudWindow, behind-window) hosting `DesktopWidgetView`: `store.inbox` newest first capped at 40 rows in huge type, rows tap to open, hover × to clear, context menu, no scrollbar but the list scrolls by wheel/trackpad (a local `.scrollWheel` event monitor gated on the panel and the view's bounds: a representable in the responder chain would win AppKit hit-testing and eat the clicks) and pans by press-and-drag (a `DragGesture` over a hand-rolled `offset`, content height measured with `onChange` inside a background GeometryReader because a preference set there never reached the outer reader), so the panel is *not* movable by background: the grabber pill at the top (`WindowDragHandle`, `performDrag`) moves it. Title size is free-typed in Settings (`widgetTitleSizeRange` 16...96 pt), and a spring `.animation` on the id list with a move-from-top transition so arrivals slide in. The inbox hold applies to it like the popover. **AX note**: while the widget is on, the panel counts as a window of the process, so `count of windows = 0` no longer means "popover closed"; find the popover as the window that has `radio group 1 of group 1` (see the scratch `popover.applescript` pattern) before clicking tabs.
- **`MenuBarIcon`** — pre-rendered NSImage variants of the mascot (monochrome template / coloured / head-only-coloured × eyes-up / eyes-down-tilted, plus 16 animation frames × 2). State priority lives in `VestitelApp.menuBarLabel`: animation > colour signals (if `allowColoredIcon`) > monochrome; eyes-down whenever the inbox is non-empty. Monochrome variants are true template images (eyes/mouth are alpha punch-outs); partially-coloured variants can't be templates, so their waves use fixed mid-gray.
- **`SyncEngine`** — optional multi-Mac sync through any shared folder (Google Drive etc., set via `settings.syncFolderPath`). Each machine writes only its own `vestitel-<machineID>.json` and merges the others' on launch, after every refresh, on popover open, and whenever a `FolderWatcher` (FSEvents on the sync folder, 2 s coalescing, `IgnoreSelf` so our own writes don't re-trigger; the same class watches the local events folder) sees another machine's file change — no file has two writers, so the transport can't conflict. Merge rules: unions everywhere; `seen` keeps the latest date (presence is what makes never-show-again propagate; the date says when a feed last carried the item); cleared beats inbox (restore loses across machines by design); deletions travel as tombstones (`removedFeeds`/`removedBookmarks`/`archiveClearedAt`) because absence is not a signal; remote feed ids are remapped to local ones by URL; a locally-seen id with no local article means "already purged here" and is never re-adopted. Settings stay per-machine unless a Mac turns on `settings.syncPreferences`: its document then carries `syncableSettings` (everything except `syncFolderPath` and the toggle itself) plus `settingsUpdatedAt`, and among Macs with the toggle on the newest stamp wins wholesale (`adoptRemoteSettings`, no per-field merge, so deletions need no tombstones). The stamp bumps only when a *syncable* field changes, and never during `load()` or adoption (the `adoptingSettings` flag), so enabling the toggle on a second Mac can't clobber the first one's setup. In `load()`, `settings` must be assigned last — its `didSet` fires `save()` → `writeSyncDocument()`, which must see the loaded `machineID`.
- **`SourcePalette`** — per-feed colours. Automatic assignment must stay deterministic for the same *set* of feed URLs: FNV-1a hash (Swift's `Hasher` is seeded per launch — never use it for anything persisted/displayed-stable) + CIELAB ΔE-aware slot probing in URL-sorted order. Manual `colorIndex` overrides always win.
- **`Views/`** — `ContentView` (header + tab switch + shared row components), `InboxView` (groups, `SmartInboxBar` subtab strip; inside a group `ArticleRow` gets a `GroupPlacement`: the group's one photo (the first member with an image) is a `GroupBanner` flush under the header band, edge to edge and inset only by the block's 1 pt border (`flush: true`: square corners, no hairline) (the photo's own aspect ratio down to 2.4:1, then a centred cover crop; decoded images cached per process), so no grouped row has a thumbnail; the `.lead` row keeps the full action bar, `.member` rows keep bookmark/link/share as small always-present icons at the end of the meta line; the header carries the group's newest time and a clear × (the header is a solid band, tint at 0.92 with white text, top corners rounded and all four when collapsed, and no left colour bar (it collided with the band's corner): the popover material is translucent, so a tinted label vanished over a backdrop of the same hue, and a plain label read as one more article title; picked from a four-way canvas over dark, blue, orange and light backdrops) that, like every row's ×, is a hover-revealed `RowActionButton` with its frame always reserved; the whole band toggles collapse through `.onTapGesture`, the × being a Button keeps its own clicks, and the swipe `DragGesture` needs 6 pt so a click never reaches it). Every tab's ScrollView content carries `.overlayScrollers()`, which forces overlay-style scrollers on the backing NSScrollView: with legacy scrollers (macOS turns them on whenever a mouse is connected) the content narrows by 15 pt as soon as a list overflows and every trailing × jumps, `ClearedView` (also hosts Archive views; "Filtered (N)" toggle for muted-keyword catches), `BookmarksView`, `SettingsView`. `Tools/make-icon.swift` draws the app icon; keep it visually in sync with `MenuBarIcon`.

## Hard-won constraints (violating these reintroduces fixed bugs)

- **Swipe gestures**: `DragGesture` on a view that moves with its own offset MUST use `coordinateSpace: .global`; local space feeds the offset back into the translation and oscillates. Row/group swipe uses the "drop target" pattern: fixed-size pane at the destination edge, layered *above* the row, armed at 75% of `actionWidth`, commit on release while armed. The row gets an opaque `windowBackgroundColor` background while dragging so the pane never shows through. Clicks are detected inside the gesture (`dragIsHorizontal == nil` on end), not via `onTapGesture`.
- **Row layout is hover-invariant**: action buttons never appear/disappear in ways that reflow text — they fade via `opacity` with `allowsHitTesting` gated (`RowActionButton.visible`), or are always visible (the bookmark/link/share bar, also `RowActionButton`s). All row icon buttons share `Image.rowActionLook`; no button has a box at rest, the hover fill appears in one step with no `.animation` (a background *fading* in from transparent is what reads as a blink); `quiet` (the bookmark/link/share bar) only dims the icon a little more at rest. The per-article clear × (hover-revealed) stays top-right regardless of card height, with Open in Browser under it (beside it in compact rows), and at the same x whether or not the list scrolls (see `.overlayScrollers()`). Rows, group blocks and the buttons also carry `.hoverRefresh`, an AppKit probe that re-checks the pointer against the view's frame whenever that frame changes, because `onHover` only fires on pointer movement and the row that slides under a still cursor after a clear would otherwise never show its ×. Every hover-highlighted button tracks the pointer through `.debouncedHover`, never a bare `.onHover`: a `.help()` tooltip installs its tracking area on first hover, which arrives as an exit + enter pair and makes a directly bound highlight flash.
- **Codable evolution**: every new persisted field must decode tolerantly — optional field, or `decodeIfPresent` with default in a custom `init(from:)` (`AppSettings` already has one; `PersistedState` uses optionals). A decode failure silently loses the user's entire state.
- **Filled images must be clipped at the image**, not only by an outer `clipShape`/`frame`: a `scaledToFill` image overflows its frame, and the invisible overflow still hit-tests, so a banner cropped to a band swallowed clicks on the group header's × and a square thumbnail reached into the row's × column. `ArticleThumbnail` and `GroupBanner` apply `.clipped()` on the image itself (the banner is also `allowsHitTesting(false)`).
- **No ticking timestamps** in the UI: use `Date.articleDisplay` (absolute, time-only for today), never `Text(_, style: .relative)`.
- Articles ingested without a publish date get `published = fetch time` by design (displayed as "when it was added").
- `MenuBarExtra` label updates are driven by `@Published` changes on the store; the popover's `onAppear`/`onDisappear` set `popoverOpen` and acknowledge `hasUnseenArticles` — that's the only "is the app open" signal available.
- **Inbox hold**: while the popover is open on the Inbox tab, arriving articles (fetch or sync merge) are hidden behind `inboxHoldStart` (a fetchedAt cutoff, in-memory only) so the list never shifts mid-read; a "N new" header button moves the cutoff forward, closing the popover or leaving the tab drops it. Anything that adds inbox articles must give them `fetchedAt = now` (sync adoption does this deliberately), and anything operating on "all inbox articles" must skip held ones (`clearInbox` does — never clear what was never shown).
- The whole-row tap on Settings toggle rows (`SettingRow.onTap`) is intentional; keep it when adding toggles, skip it for pickers.
